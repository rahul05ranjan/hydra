# Hydra self-improvement log

What real use of Hydra shows, and what to change because of it. The evidence comes from the local telemetry (`~/.hydra/ledger.jsonl`, read with `hydra improve`) and from what an agent noticed while working. Add an entry after any session that used Hydra; close an entry when its fix lands.

Each entry: date, what was seen, the evidence, and its status (open, fixed, by design). Token figures are estimates (characters / 4). Run `hydra improve --since <date>` for the numbers since a given day.

Do not use failures from the sealed `evals/git1` set to decide changes here; that rule in `AGENTS.md` still holds.

## Fixed

- **2026-10-17. The test hook turned back runs the agent had already cut short.** `testRun` in `lib/claude_hooks.mjs` now looks at each run's own pipeline: a later `tail`/`head` keeping at most 40 lines (10 when not given), `grep -c` or `wc` lets it through, recorded as hook decision `trimmed` (counted by `hydra improve`). `tail -f`, `tail -n +N`, a plain `grep` and a second run without a cut are still turned back. The deny message says so, so the agent can trim instead of reaching for `HYDRA_RAW=1`. Replayed against the ledger: of the 11 denials and 18 raw bypasses recorded on 10-17, 23 would now pass as already cut, 2 are still turned back (a bare `node --test`, and `pnpm test | grep -E ...`), and 5 could not be replayed because the ledger keeps only the first 300 characters (their full commands in the transcripts all end in `| tail -N`). Tests in `test/claude_hooks.test.mjs`; installed here (Claude Code skill, `~/.agents`, `~/.hydra/scripts`, the Antigravity IDE skill).

- **2026-10-17. Antigravity IDE gets Hydra where it looks.** New tool `antigravity-ide` in `lib/integrations.mjs`, detected by `~/.gemini/antigravity-ide`: the MCP entry goes to `~/.gemini/config/mcp_config.json`, and the skill folder (SKILL.md plus the scripts it names) to `~/.gemini/config/skills/hydra`, replacing an older hydra skill there and leaving any other folder alone. `installSharedScripts` now keeps SKILL.md beside `~/.hydra/scripts` for that copy. The old `antigravity` target stays for the older app. Regression cases in `test/integrations.test.mjs` (empty config file, stale skill replaced, other skills untouched, clean removal). Applied here with `hydra agents install antigravity-ide`: the empty config is backed up as `mcp_config.json.before-hydra`; the IDE's skill copy now runs `hydra doctor` with exit 0 (it failed with `hydra-nano:git missing` before) and answers a git question.
- **2026-10-17. Antigravity's calls were recorded as `shell`.** `caller()` knew only `HYDRA_AGENT`, `AI_AGENT` and `CLAUDECODE`, which Antigravity does not set, so the 28 `shell` rows of 10-17 (10:51 to 11:18 UTC, inside IDE session `f2a3fb13` in this repo) were its calls. macOS passes the launching app's bundle id to child processes (this Claude Code session sees `__CFBundleIdentifier=com.microsoft.VSCode`), so `com.google.antigravity-ide` or `com.google.antigravity` now records `agent: antigravity` with the bundle id as `agentDetail`; Claude Code inside Antigravity's terminal stays `claude-code`. Test in `test/ledger.test.mjs`. That Antigravity's own processes carry this bundle id is inferred, not yet seen in a live IDE session. Older rows stay `shell`.

- **2026-10-17. The refactor tests wrote fixture calls into the user's ledger.** `test/refactor.test.mjs` ran the real CLI (`smell`, `refactor`, `design` on a temporary file) without `HYDRA_TELEMETRY=0`, the same mistake as `test/runtime.test.mjs` below: 12 of the refactor head's 25 rows are its `/var/folders/.../hydra-refactor-*` fixtures. Its CLI calls now set `HYDRA_TELEMETRY=0`; 8/8 tests pass and a run adds no ledger rows. Older fixture rows stay in the ledger.

- **2026-10-17. A short pass now returns the output alone, and every other reply names the program without its directory (`/home/u/.venv/bin/python -m pytest` -> `python -m pytest`). The same command now returns 29 -> 29. Test-log benchmark unchanged: 19/20 solved, same task per task; returned 2,615 -> 2,613 tok (its commands are already short).
- **2026-10-17. Hook rows and CLI rows named the agent differently** (`AI_AGENT` is `..._harness` in hooks, `..._agent` in the shell). `agent` now keeps the family (`claude-code`) and `agentDetail` the full value.

- **2026-10-17. Rows written before this fix are still in the ledger; use `--since 2026-10-17T05:00Z` for clean numbers (a time without `Z` is local time).
