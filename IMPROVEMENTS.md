What real use of Hydra shows, and what to change because of it. The evidence comes from the local telemetry (`~/.hydra/ledger.jsonl`, read with `hydra improve`) and from what an agent noticed while working. Add an entry after any session that used Hydra; close an entry when its fix lands.

Each entry: date, what was seen, the evidence, and its status (open, fixed, by design). Token figures are estimates (characters / 4). Run `hydra improve --since <date>` for the numbers since a given day.

Do not use failures from the sealed `evals/git1` set to decide changes here; that rule in `AGENTS.md` still holds.

- **2026-11-20. The Read head's outlines and symbol slices disagreed with the language parsers.** Found by checking Hydra against the Read gold builder's own parsers (stdlib `ast`, pinned tree-sitter, installed into `~/.hydra/quality-parsers` as the builder's header says) on every development-split source file, never a held-out one (the inventory marks each file's split). Before: Go outlines matched exactly in 369 of 585 files (63%): JavaScript's `var x =` pattern caught Go `var` blocks, and generic funcs (`func Map[T any](`), non-struct types (`type Mode int`), aliases and grouped `type (…)` specs were missed. Symbol slices were about 99%: lookups were case-blind (Go `insert` found `Insert`), JavaScript's `let x =` matched Rust locals (`let len = self.len()`), Python one-line defs ran on, trailing comments extended blocks, a `def` inside a triple-quoted string won, a `'file://'` string hid a brace from the counter, Rust trait signatures beat their `default fn` bodies, and a multi-line bodyless Go func ran into the next one; JavaScript generators and Rust `unsafe trait` were missing from outlines. `read.mjs` now uses per-language definition rules, exact-case matches first, string-aware scanning for Go raw strings and Python triple quotes, and parser-shaped block ends. After: 884/884 development files' outlines and 7,070/7,070 development symbols match the parser. Read development 200/200 (was 199). Read held-out, scored once afterwards: 982/1,000 (98.2%, was 961). Five tests in `test/read-quality.test.mjs`, each failing on the old code.
